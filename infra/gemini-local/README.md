# Local Gemini access with Firebase emulators

This isolated Terraform root manages the API Keys and Generative Language APIs, the Resource Manager API prerequisite, one dedicated service account, and a service-account-bound API key restricted solely to `generativelanguage.googleapis.com`. It does not manage Firebase, deployment, Cloud Build, or organization policy. Existing IAM and Service Usage APIs must be discovered and recorded separately. If an API, identity, or matching key already exists, import it before management instead of recreating it.

The optional `enable_vertex_ai = true` adds only `google_project_service.vertex_ai[0]` for `aiplatform.googleapis.com`, using the same authorized project, ephemeral provider token, and private state. Its default is `false`, and it also requires `provision_gemini = true`. Before opting in, discover the API's existing state and Terraform ownership. If already enabled, import the service into this address; otherwise the existing managed setup should plan exactly one additional API. Retain the private flag on future plans because deletion protection rejects removing managed API resources. Record discovery, planned enablement or import, and the eventual verified result separately in the infrastructure inventory.

For local Gemini publisher-model requests through Vertex AI, use the explicitly verified user's short-lived OAuth token with an explicit backend project and quota project. The documented prompt permission is `aiplatform.endpoints.predict`; using the quota project also requires `serviceusage.services.use`. Verify existing permissions before adding any grant. Enabling the API needs `serviceusage.services.enable`, already needed by this root's API management. This optional resource adds no IAM bindings, endpoint deployment, or credentials; the existing bound authorization key stays restricted solely to the Generative Language API. The application must not fall back to shared ADC when the explicit token is missing or expired. [Google quickstart and OAuth REST request](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/start/quickstart), [prompt permissions](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/access-control), [quota-project permissions](https://docs.cloud.google.com/docs/quotas/set-quota-project).

Google Cloud Welcome credits cannot pay for Gemini Developer API / AI Studio usage. Vertex is a separate Cloud billing route for Google models; the Free Trial coverage page excludes partner models and AI Studio usage, while allowing covered Cloud products. Confirm the actual billing account's eligible credit, expiry, model availability, and a successful bounded request before recording live success. API enablement alone does not establish any of these. [Gemini Developer API billing](https://ai.google.dev/gemini-api/docs/billing), [Google Cloud Free Trial coverage](https://docs.cloud.google.com/free/docs/free-cloud-features).

Google's September 2026 requirements reject standard Gemini API keys. Google provider 8.1.0 does not expose the documented `serviceAccountEmail` API Keys field, so the pinned `magodo/restful` provider manages that key through a normal Terraform resource with create/read/update/delete, drift detection, and asynchronous operation polling. The standard Google provider still manages APIs and the service account. The key's service restriction uses Google's built-in Gemini exception to the authorization-key organization policy. No policy change or broad service-account role is granted. [Gemini key requirements](https://ai.google.dev/gemini-api/docs/api-key), [Google authorization-key creation](https://docs.cloud.google.com/docs/authentication/api-keys), [pinned Google provider key schema](https://github.com/hashicorp/terraform-provider-google/blob/v8.1.0/google/services/apikeys/resource_apikeys_key.go), [RESTful lifecycle provider](https://registry.terraform.io/providers/magodo/restful/0.25.2/docs/resources/resource).

Use the repository's verified-profile secure launcher for authenticated plan/apply. Both providers use the same ephemeral `access_token`, never an implicit ADC identity. Quota is explicitly charged to `project_id`. The launcher initializes the local backend with an absolute state path under the outer private directory, verifies the cached backend path on subsequent runs, and binds each saved plan to its profile, account, project, state path, and file digest in a private context manifest. It keeps plans private, disables provider/debug logging, and preserves shared ADC. Supply actual identifiers only from private configuration. Do not apply from a default local state path.

The live provider refresh exposed a required Resource Manager API lookup after initial API enablement. If that prerequisite is disabled and prevents a full refresh, the launcher's `bootstrap-plan` action targets only `google_project_service.resource_manager[0]`. Review and apply that saved plan, then run a full `plan` and `apply`. This is a narrow prerequisite recovery; normal work must use the complete graph. The launcher rejects any bootstrap plan that changes another resource.

Terraform exports only metadata. The key resource additionally allowlists metadata response fields and marks its response sensitive. The private launcher may read `getKeyString` after checking the exact resource's project, service-account binding, and sole Gemini restriction, saving the payload directly to a private Gemini JSON file without displaying it. Never print state, plan JSON, HTTP debug traces, or credential responses. State and backups must remain private even though this root intentionally does not request a key string.

The default `provision_gemini = false` produces zero resources. Enabling provisioning also requires a non-emulator project ID and a nonempty ephemeral token from the authorized profile. Deletion protection prevents an accidental opt-out, ID change, or destroy from deleting resources. Rotate or remove the key only through an explicitly reviewed future Terraform change.

Offline checks use mock providers and generic identifiers. They validate opt-in, emulator-project rejection, explicit authentication, the service-account binding, the sole Gemini restriction, API preservation, metadata-only outputs, and asynchronous error discrimination. Mock results do not prove actual IAM, billing, model availability, or live generation; those require the separate live verification record.
