  Adoption rule: test Pascal against our Next.js/React versions, real openings, millimetre round-trips, local assets, controlled
  persistence, graphics fallback and performance budgets. Adopt its useful modules if those checks pass. Otherwise retain Three.js/R3F
  and implement the bounded architectural generators behind the same scene contract.

  Use a matched, pinned package release. Keep Firebase ownership, revision history and saving under our API’s control.

  The shared contract will have three principal types:

  - PlanCandidate: extracted walls, rooms, openings, dimension labels, source coordinates and uncertainties.
  - SceneDocument: validated architecture, catalog instances and materials, with integer-millimetre dimensions and stable IDs.
  - ScenePatch: a bounded list of permitted edits.

  For example, an LLM-generated edit could be:

  {
    "schemaVersion": 1,
    "operations": [
      {
        "op": "setMaterial",
        "entityId": "wall-3",
        "surfaceId": "living-room-facing",
        "materialId": "paint-warm-white"
      }
    ]
  }

  Ownership, selection permissions and the base revision belong to the server-controlled request context. The model cannot change them.
  JSON parsing, schema validation, geometry checks and permission checks all precede publication.

  ## 3. Image reading and precise editing

  ### Specialised image-reading agent

  Move the Surveyor role forward from v2. Run Surveyor and the targeted-edit Stylist as two bounded roles in one local spatial worker
  using official TypeScript ADK. Move the ADK compatibility check to the beginning; use a repository-local Node 24 runtime for that
  worker while preserving the existing API runtime.

  The first image flow will:

  1. Accept PNG/JPEG floor-plan images, bounded to 4 MiB and 20 megapixels.
  2. Preserve the original privately and record crop/rotation transformations.
  3. Have Surveyor return a PlanCandidate, with references back to the drawing.
  4. Overlay extracted walls, openings and labels directly on the image.
  5. Ask for a known dimension when scale is missing; highlight contradictory or uncertain details.
  6. Allow correction in the same screen before creating the saved scene.

  A valid-looking JSON response does not establish accurate geometry. Unknown scale cannot become confirmed dimensions. Ceiling height,
  window height and finishes absent from the drawing remain labelled assumptions.

  ### Selection before AI edits

  Require an explicit target before enabling Ask for a change:

  - Click/tap an object, wall surface or room in 2D/3
D.
  - Draw an adjustable rectangle in Plan view for an area, including empty space.
  - Use the semantic list and labelled controls as keyboard/touch alternatives.

  Show the selected target prominently: “Editing: living-room window wall.” Area selection also shows the affected objects.

  Each request freezes a SelectionScope: scene revision, selected IDs, surface or plan-space region, and permitted operation types.
  Neighbouring geometry may provide collision context without granting permission to edit it.

  The server enforces:

  - Existing-object changes affect only selected entities.
  - New placements respect the selected area or mounting surface.
  - Locks, dimensions, collisions and clearances remain valid.
  - A changed scene revision triggers conflict handling.
  - Broader changes require the user to expand the selection explicitly.

  Valid furniture/material edits save automatically to a reversible working option. Compare, Undo and Use this option remain available.
  Architectural alterations stay in the explicit manual layout-editing flow.

  ## 5. Setup, contracts and autonomous testing

  Local setup: retain the planned preview at 127.0.0.1:3100, API on 8181 and separate Auth/Firestore emulators on 9299/8285. Use a
  dedicated branch/worktree, isolated build output and persistent demo snapshots. Keep uploads outside the public web directory and
  build archive. Live model configuration stays external and server-side.

  API additions: retain scene/catalog routes and add owner-authorized plan upload/read, job start/status/cancel, candidate acceptance
  and selected-edit requests. Large uploads use a separately bounded binary route; the 48 KiB JSON gateway limit stays intact.

  Durability: immutable revisions and bounded chunks, content written before the head transaction, request deduplication, preserved
  conflicts and exact historical change-card references. Jobs retain their stage, attempt and result across restart. Cancellation
  prevents late publication.

  AI limits: one active spatial job per owner; one extraction attempt plus one explicit retry per source revision; at most two model
  rounds, four tool reads per round and eight operations per edit patch. Reserve every model attempt before dispatch. Viewing,
  selection, orbiting and saving make no model calls. Unknown outcomes never silently redispatch.

  Generated test input: create one accurately drawn single-room PNG from a deterministic source: a 5 × 4 m room, labelled wall
  thickness, one door and one window. Keep its ground-truth geometry in the test harness; the live agent receives the image, not the
  answer. Rotated, blurred and unscaled variants reuse that same room.

  Automated checks will cover:

  - Extraction entity counts, dimension labels, opening placement and geometry error against ground truth.
  - Separate automatic and user-corrected results; malformed or ambiguous inputs enter useful correction states.
  - Creation/edit syntax, invalid IDs, forbidden operations, out-of-selection edits and locked objects.
  - Collision, mounting, topology and unit round-trips.
  - Duplicate jobs, budget exhaustion, cancellation, stale results, failed saves and cross-user denial.
  - Browser journeys at 1440, 390 and 320 pixels, including keyboard, non-drag touch and no-WebGL operation.
  - Existing proposal/room regressions, build/type/lint/Rules checks, visual inspection and public-file scanning.
  - First-view asset targets of 5 MB desktop/3 MB mobile, with measured rendering performance and repeated-entry disposal checks.

  Routine tests use explicitly labelled deterministic responses; bounded live runs verify actual image reading and targeted edits
  separately. One generated room proves the initial pipeline, not universal floor-plan accuracy; broader recognition claims require the
  planned held-out benchmark.

  Commit each verified stage. Deployment, cloud storage provisioning through Terraform, completed Google consent and genuine AI Studio
  evidence remain separate release gates. The wider agent crew, website embedding, new spatial sharing/exports and multiple floors
  remain in later releases.
