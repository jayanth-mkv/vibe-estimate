Ordered by value, not by dependency. Each item is independently shippable, and none is required for the [v2](v2.md) submission to stand on its own.

## Multiple floors

Deferred from v2 by explicit decision — launch sooner with full apartments and single-floor homes.

Multiple source pages and levels, explicit floor alignment and heights, stair links, cross-floor navigation. The `levels[]` array shipped in [v1](v1.md#scene-foundation) with one level populated makes this additive rather than a rewrite.

**Gate:** an entire multi-storey benchmark home; stair and level consistency; per-level performance measured separately; version and source continuity across levels. A separate verified whole-house snapshot.

## Real embed SDK

[v2](v2.md#build-order) hosts a page that plays the role of the designer's website. v3 makes it a genuine script-tag widget a designer drops onto their own site.

- A lightweight loader injecting an isolated iframe, with `postMessage` for host-to-widget communication and a small JS API for programmatic control.
- An origin-bound tenant key, so a stolen embed snippet does not work from another domain.
- Per-tenant CSP `frame-ancestors` **replacing** the global `X-Frame-Options: DENY` in `next.config.ts` for the widget route only. Never weaken it globally.
- Per-tenant appearance configuration through the console.

**Gate:** cross-origin isolation, a stolen-snippet test from an unlisted origin, host-page CSS containment, and confirmation that the widget route's relaxation does not reach any other route.

## Voice

`gemini-3.1-flash-live-preview` over WebSocket — raw PCM 16-bit mono, 16 kHz in and 24 kHz out — with ephemeral client tokens so no long-lived credential reaches the browser. The homeowner simply talks while watching their home build.

Voice activity detection, session management, and an always-available text fallback. Never the only way to use the product.

**Gate:** token expiry and renewal, session resumption, a noisy-input case, and the text path proven equivalent.

## More MCP

Extends the single Catalog MCP from [v2](v2.md#mcp).

| Server | Consumed by | Why |
| --- | --- | --- |
| **Rate-card MCP over BigQuery** | Scope | The designer's *own* past project rates, reusing the `cloud-run-adk-bq-mcp` pattern. Answers "what did you charge for this last time?" by citing their history rather than inventing a number. A cited past rate is still a suggestion the designer must confirm. |
| **Google Maps MCP** | Sourcer | Local availability, nearby showrooms and suppliers, realistic lead times. |
| **Vendor catalog MCP** *(third party)* | Sourcer, Stylist | Real products from real suppliers, entering the same admission checks as any other asset. |

### Published

- **Scene MCP** — read-only scene tools (`get_scene_context`, `measure_selection`, `list_change_cards`) so a designer's own tooling, or a Gemini or Claude CLI, can inspect a project under the same Firebase identity and the same ownership checks. No write access, ever.
- **A2A agent cards** at `/.well-known/a2a`, so another firm's agent could request a quote from this designer's crew. That is the ecosystem in its literal form.

**Gate:** the same untrusted-data rules as v2 — a vendor server cannot steer an agent, cannot write, and cannot set a price. Scene MCP enforces `assertOwner` and `memberRole` identically to the HTTP API.

## Room-time

- Collision-aware walkthrough with room stops, previous and next, saved viewpoints, and optional free movement.
- A **show me what changed** path that flies to each change card in order — the shareable reel.
- Opt-in **Present my view** and **Follow**, with **Stop following** and **Return to my view**. Every presentation event is bound to a room and a shared snapshot accessible to its audience; a private option can never be broadcast by following. If versions differ, offer to open the shared snapshot while preserving the follower's work and camera. Recheck membership on connection and renewal; reject anchors outside that snapshot.
- An authenticated, throttled event channel for presentation. Pointer and camera presence is temporary — it must never write Firestore every frame or trigger Gemini. Reconnect from the last saved revision and expire presence rather than inventing online state.

Do not make pointer lock or a game-style keyboard scheme the only way to inspect the home. Room stops and previous/next come before free movement. Escape always exits captured camera input.

**Gate:** door and wall collision, mobile motion controls, disconnect and reconnect, presence expiry, and denial of following into an unpublished revision.

## Commercial depth

**Multi-line proposals.** Extend the proposal, `SharedDraft`, the saved request and replay payload, evidence and export schemas *together* to versioned line-item arrays. Treat old drafts as one-line historical revisions, preserving their exact totals and exports. Retries compare the complete canonical item array, evidence references and scene revision; a reused request ID with changed content is rejected.

**Quantity and money.** Store quantity in thousandths of its declared unit — counts require whole units, lengths and areas allow up to three decimal places. Convert confirmed millimetres and square millimetres to the displayed billable quantity with an explicit reviewed rounding rule. Calculate each line's paise using integer arithmetic and round half up **once**, at the line boundary; the subtotal is the sum of those line totals. Never silently add tax, waste or discounts.

Counts can be derived from admitted instances. Areas and lengths require confirmed scale and explicit measurement rules. Included work stays outside the additional-work subtotal. The owner confirms commercial descriptions, unit, quantity, rate and any waste or labour factor. Missing rates remain questions. No model-generated market price, and no approval inference.

**Gate:** non-integer measurements, included items, missing rates, rounding boundaries, and old and new shared and exported records all preserved exactly.

## Exports

Three distinct outputs:

1. **Editable project JSON** with scene semantics.
2. **Derived GLB** for a 3D viewer.
3. **A plan or image plus a change sheet and proposal document.**

Export a clean scene from the canonical revision rather than the currently hidden or cutaway viewport. GLB excludes private messages and source files and is validated and reloaded independently. JSON restore validates its schema and catalog dependencies, creates a new owner-authorized project, and **never trusts imported owner IDs, storage locations or source grants**. A generated presentation image, if offered, is labelled illustrative and tied to its source revision.

Client export stays unavailable until deliberately designed.

## Evaluation at full strength

The complete **12-plan annotated benchmark**: clean complete homes, rotated and cropped plans, low-resolution scans, and ambiguous or unscaled sources. Some plans held out from prompt tuning. Synthetic tests kept separate from consented real-plan evidence.

Record room and connectivity accuracy, confirmed-scale wall and opening error, missing entities, correction actions and time, model calls and latency for each input. Low-quality inputs must reach a useful check or correction state. **Publish measured results and failures** rather than claiming general accuracy from the showcase example. Record the automatic result separately from the human-corrected result.

The first user study tests whether a new visitor can understand the purpose, calibrate a plan, save an idea, find the other person's option and produce a draft without coaching. Observed completion and confusion guide refinement.

## Image-to-3D assets

Future image-to-3D assets go through dimension, mesh, licence and performance checks before entering the same admitted catalog as any other asset. A GPU-backed Cloud Run worker pool — NVIDIA L4 or RTX PRO 6000 — handles generation.

AI-generated imagery can help choose a mood or develop a texture concept. **Do not run a mesh-generation service for every drag, and never render a 2D furniture picture as if it were a 3D object.**
